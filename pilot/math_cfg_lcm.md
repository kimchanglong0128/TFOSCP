## 第 1 部分:CFG 是什么(隐式分类器视角)

### 1.1 起点:classifier guidance(Dhariwal & Nichol 2021)

想从条件分布 p(x|c) 采样。对 Bayes 公式取 log 再对 x 求梯度:

```
p(x|c) = p(x) · p(c|x) / p(c)

∇ₓ log p(x|c) = ∇ₓ log p(x) + ∇ₓ log p(c|x)          (p(c) 与 x 无关,梯度为 0)
                └─无条件 score─┘  └─分类器梯度─┘
```

原始做法:训一个能吃噪声图的分类器,用它的梯度 ∇log p(c|x_t) 推着采样往"更像 c"走。

### 1.2 CFG:不训分类器,把它"变"出来

把 1.1 的式子移项:

```
∇ₓ log p(c|x_t) = ∇ₓ log p(x_t|c) − ∇ₓ log p(x_t)
                   └─条件 score──┘   └─无条件 score─┘
```

**右边两项同一个网络都能算**(条件输入 c / 空条件 ∅)。所以分类器梯度 = 两个 score 之差,不需要显式分类器——这就是 classifier-**free**。

### 1.3 引入强度 w

把分类器梯度放大 w 倍再加回去:

```
∇ₓ log p̃_w(x_t|c) = ∇ₓ log p(x_t) + w · ∇ₓ log p(c|x_t)
                    = ∇ₓ log p(x_t) + w · [∇log p(x_t|c) − ∇log p(x_t)]
                    = (1−w) · ∇log p(x_t) + w · ∇log p(x_t|c)
```

换成噪声预测语言(ε ∝ −σ_t · score):

```
ε̂(x_t, c) = ε_θ(x_t, ∅) + w · [ε_θ(x_t, c) − ε_θ(x_t, ∅)]        ← 你在代码里见到的 CFG 公式
```

### 1.4 关键理解:CFG 定义了一个新分布

上面的 score 对应的分布是:

```
p̃_w(x|c) ∝ p(x) · p(c|x)^w
```

w = 1:就是原本的 p(x|c)。
w = 7.5:把"分类器认为像 c"的程度**指数放大 7.5 倍**——分布被尖锐化,质量集中到"最典型的 c"区域。

**为什么 w 太大会过饱和**:p(c|x)^w 在 w 很大时把所有质量推到分类器最有信心的极端样本上——那些是"c 的漫画式夸张版",不是自然样本。分类里的过拟合直觉直接迁移。

> ⚠ 记住:**CFG 不是后处理装饰,它改变了 PF-ODE 的向量场**。开 CFG = 在解另一条 ODE。

## 第 2 部分:LCM 蒸馏的是哪条 ODE

### 2.1 一致性蒸馏的目标

一致性函数 f_θ(x_t, t) 学的是:把 PF-ODE 轨迹上任意点映到该轨迹的终点 x_0。
Teacher(SDXL)负责生成轨迹,student 学"任意点 → 终点"的直接映射。

### 2.2 Teacher 开着 CFG 生成轨迹

LCM 蒸馏时,teacher 每一步算的是 **1.3 里的 ε̂(带 w)**,不是裸 ε_θ。
所以 teacher 走的是**尖锐化分布 p̃_w 的 ODE 轨迹**。

```
f_θ 学到的 = p̃_w 的 PF-ODE 的解映射
           = "开着 w 的 CFG 走到底会落在哪"这张地图
```

**guidance 的全部效果被烧录进了权重。** 权重本身就是尖锐化轨迹的地图。

(原生 LCM 还把 w 作为 Fourier 嵌入输入,可以在一个范围内调;LCM-LoRA 没有这个输入口,烧的是固定的一份。)

## 第 3 部分:推理时再开 CFG 会怎样

如果传 guidance_scale = w' > 1,diffusers 做两次前向并套 1.3 的公式:

```
ε̂' = f_θ(x_t, ∅) + w' · [f_θ(x_t, c) − f_θ(x_t, ∅)]
```

两个问题叠加:

**(a) 双重尖锐化**
f_θ 内含一层 w,外面再乘 w'。等效分布量级为:

```
p(x) · p(c|x)^(w · w')
```

w = 7.5(蒸馏时)× w' = 8(推理时)≈ 60 倍尖锐化 → 轨迹飞出数据流形 → 图像崩塌。

**(b) uncond 分支无意义**
f_θ(x_t, ∅) 学的是"空条件下尖锐化轨迹的终点",它不是"未尖锐化的基线"。
拿它做 CFG 的减数,是在对两个不该相减的量做外插。

---

## 第 4 部分:w' = 1 的精确含义

```
w' = 1  →  ε̂' = f_θ(x_t, c)        (uncond 项系数归零)
```

diffusers 内部判断 `guidance_scale > 1` 才启用 CFG;= 1 时**直接跳过 uncond 前向**。
语义正确(只用权重里那份 guidance),计算量还省一半。

## 第 6 部分:与论文 H3 的连接

H3:单步生成中 CFG 的单次全额施加 / 截断误差是身份坍塌的来源。

本笔记建立的事实链:
1. 蒸馏模型里 guidance 是**烧在权重里、一步兑现**的(第 2 部分)
2. 多一分都是灾难(第 3、5 部分)
3. 因此单步下 guidance 方向与身份方向的**任何非正交分量**都没有后续步骤来纠偏(理论图·枝 2)

这解释了两个竞争者的经验现象:
- When Few Steps Are Enough:关掉 CFG 身份反而好 → 第 3 部分 (a) 的直接预言
- FastFace:必须重新设计 CFG(α/β 解耦)才能在蒸馏模型上用 → 第 3 部分 (b) 的工程回应
